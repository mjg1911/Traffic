# Lane Connections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let players edit which outgoing lane each incoming lane can reach at a junction while leaving untouched lanes on automatic routing.

**Architecture:** Store manual per-source-lane movement lists on each junction using stable edge IDs, directions, and lane indices. Generate the live connector graph from those lists when present, otherwise keep the current automatic `lanePairs` rules. Add a Canvas editor tool that toggles lane-to-lane movements, then reuse the current route finder, signal/conflict generation, reservation arbiter, and save migration paths.

**Tech Stack:** Vanilla JavaScript, Canvas 2D, HTML/CSS, browser-local JSON saves.

## Global Constraints

- Keep automatic lane-routing behavior for every unedited lane.
- Allow one lane to connect to multiple outgoing lanes, including movements not selected by the current automatic lane-pair rule.
- Ensure route finding and lane changes never use a disabled connector.
- Preserve the custom choices across save, load, export, and import; older saves use automatic rules.
- Require at least one valid exit for each manual lane; refuse to remove its last exit.
- Roundabouts remain automatic, and the current restriction on mid-junction U-turns remains in force.
- Bump city saves from version 3 to version 4 and preserve the existing version 1 through 3 migrations.
- Preserve all existing uncommitted workspace edits.
- Do not add or run automated tests for this request.
